内嵌 buildspec 基本格式
在 CloudFormation 里，CodeBuild 项目的 BuildSpec 属性支持用多行字符串直接写 buildspec 内容，格式类似 YAML，常用写法是：
BuildSpec: |
  version: 0.2
  phases:
    install:
      commands:
        - command1
        - command2
    pre_build:
      commands:
        - command3
    build:
      commands:
        - command4
  artifacts:
    files:
      - some/path/**

注意：
用 | 开始，表示多行字符串。
内部写的内容是标准的 buildspec.yml 格式（YAML）。
缩进非常关键，确保写对层级（version、phases、commands等）。
每条命令前加 -，用数组形式列出。

你模板里的 buildspec 样例（摘录并稍微注释）
BuildSpec: |
  version: 0.2
  phases:
    install:
      runtime-versions:
        nodejs: 18
      commands:
        - echo Installing unzip...
        - yum install -y unzip || true
    pre_build:
      commands:
        - echo Downloading zip from S3...
        - aws s3 cp s3://$S3_BUCKET/$ZIP_OBJECT_KEY ./app.zip
        - unzip app.zip -d ./app
        - cd app
    build:
      commands:
        - echo Running cdk bootstrap...
        - npx cdk bootstrap
        - echo Running cdk diff for debugging...
        - npx cdk diff || echo "cdk diff failed, continuing..."
        - echo Installing npm dependencies...
        - npm install
        - echo Deploying CDK stack...
        - npx cdk deploy --require-approval=never
  cache:
    paths:
      - '/root/.npm/**/*'
      - 'node_modules/**/*'

说明
version: 0.2 是 buildspec 版本，AWS CodeBuild 推荐用0.2。
phases 里分阶段写执行命令：
install 阶段一般做环境准备，比如安装系统依赖，切换runtime版本等。
pre_build 一般做准备工作，比如拉代码、下载依赖、解压文件。
build 是构建/部署主体阶段。
每个阶段下的 commands 是一系列 bash 命令，按顺序执行。
通过 || true 或 || echo ... 可以防止某些命令失败时终止整个构建，比如这里安装 unzip 失败不会中断。
cache 配置可以加速依赖安装，比如缓存 npm 包和 node_modules，减少构建时间。
变量如 $S3_BUCKET、$ZIP_OBJECT_KEY 是 CodeBuild 环境变量，由 Lambda 传入或者模板里定义。

注意事项
命令失败默认会导致构建失败并停止，除非用 || true 或类似技巧忽略错误。
你可以用 echo 输出提示信息，方便日志阅读和调试。
内嵌 buildspec 里不要写太复杂的脚本，保持清晰易维护。
如果需要复杂逻辑，建议写脚本文件放在 ZIP 包内，通过 buildspec 调用。
缓存路径一定要写对，防止缓存失效。

-----------------------------------------范例----------------------------------------------

BuildSpec: |
  version: 0.2  # buildspec 格式版本，固定写0.2即可
  phases:
    install:
      runtime-versions:
        nodejs: 18  # 指定使用 Node.js 18 运行时环境
      commands:
        - echo "Installing system dependencies..."  # 日志输出
        - yum install -y unzip || true             # 安装 unzip，失败也继续（防止中断）
    pre_build:
      commands:
        - echo "Downloading deployment ZIP from S3..."  
        - aws s3 cp s3://$S3_BUCKET/$ZIP_OBJECT_KEY ./app.zip  # 从 S3 下载 ZIP
        - echo "Unzipping deployment package..."  
        - unzip app.zip -d ./app                               # 解压到 app 目录
        - cd app                                               # 进入项目目录
    build:
      commands:
        - echo "Bootstrapping CDK environment (if needed)..." 
        - npx cdk bootstrap                                   # 初始化 CDK 环境（可跳过已完成的）
        - echo "Running cdk diff to preview changes..."  
        - npx cdk diff || echo "cdk diff failed, continuing..."  # 变更对比，失败不阻止部署
        - echo "Installing npm dependencies..."  
        - npm install                                          # 安装项目依赖
        - echo "Deploying CDK stack..."  
        - npx cdk deploy --require-approval=never             # 无需人工审批直接部署
  cache:
    paths:
      - '/root/.npm/**/*'   # 缓存 npm 全局包，加速依赖安装
      - 'node_modules/**/*' # 缓存本地 node_modules 文件夹



这个 buildspec 的优点：
清晰分阶段，逻辑简单易懂
关键命令加了 echo，方便日志追踪
通过 || true 或 || echo 容错某些失败，保证部署不中断
缓存 npm 依赖，提升构建速度
使用 CDK 推荐命令流程，兼容首次部署和更新
